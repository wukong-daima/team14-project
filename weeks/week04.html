WEEK 04 · 학습담당: 담당 A·마지막 수정: 2026-10-31·원본: week2_fm p.56~90 + week4_agent p.84~93

LLM 학습 방법론: RLHF · DPO · GRPO · OPD

사전학습된 LLM을 "사람이 선호하는 답"과 "정답이 검증되는 추론"으로 끌어올리는 레시피(SFT → 선호 튜닝 → 추론 RL → 증류)를 배우고, 수백 스텝짜리 에이전트 과제에서 보상 희소성과 추론-학습 불일치를 어떻게 푸는지 봅니다. 2주차 개념 9·10의 심화 편입니다.

책을 많이 읽어 말을 배운 AI를 "사람 마음에 드는 답"과 "수학 문제를 맞히는 실력"으로 훈련시키는 방법을 배워요. 그리고 300단계짜리 긴 숙제를 시킬 때 생기는 문제도요.

1. 한눈에 보기

원본 위치 주의. 이 주차 요약의 선호 튜닝 내용은 2주차 PDF(week2_fm) 56~57, 68~90쪽에, 롱 호라이즌·추론-학습 불일치 내용은 week4_agent 84~93쪽에 있습니다. 2주차 페이지가 개요라면 이 페이지는 수식 구조와 에이전트 학습까지 들어가는 심화입니다.

2. 핵심 개념

CONCEPT 01 · week2_fm p.56–57

LLM 학습 파이프라인 (pt → cpt → SFT → PFT → RFT)

요약본의 "Pre-training → SFT → DPO → GRPO → OPD"는 교수님 구두 설명에 가깝고, 슬라이드의 단계 표기는 pt → cpt → SFT/IFT → PFT → RFT입니다 (p.57). DPO·GRPO·OPD는 각각 PFT·RFT·증류 단계에서 쓰는 알고리즘 이름입니다.

베이스 모델은 대규모 코퍼스로 사전학습(pt)하고 도메인 데이터로 이어서 사전학습(cpt)합니다. 그 위에 지시-응답 쌍으로 SFT/IFT를 하고, 사람 선호를 반영하는 Preference Fine-Tuning(RLHF 또는 DPO), 마지막으로 검증 가능한 보상으로 Reinforcement Fine-Tuning(PPO 또는 GRPO)을 합니다. 각 단계는 반복될 수 있고, 강한 교사 모델이 있으면 증류(OPD)가 추가됩니다. Tulu 3, Nemotron Nano 2 같은 공개 레시피가 이 순서를 따릅니다.

책을 엄청 많이 읽어 말을 배우고(사전학습), 선생님이 문제와 답 예시를 보여주고(SFT), 두 답 중 사람들이 더 좋아하는 쪽을 배우고(선호 튜닝), 수학 문제를 풀어 채점받으며 실력을 올려요(강화 학습). 순서대로 한 번씩이 아니라 여러 번 돌 수도 있어요.

CONCEPT 02 · week2_fm p.72–79, 84

RLHF (Reinforcement Learning from Human Feedback)

요약본의 "RLHF는 최대 4개 모델"은 슬라이드상 PPO 설명(p.84)에서 policy · reference · reward · value 네 모델을 말한 것입니다. RLHF를 PPO로 구현할 때라는 뜻이므로 의미는 같습니다.

사람이 매긴 응답 쌍의 선호로 보상 모델(Reward Model)을 먼저 학습하고, 정책 모델이 그 보상을 최대화하도록 PPO 같은 온라인 RL로 학습합니다. 레퍼런스 모델과의 KL 페널티가 분포 붕괴를 막습니다. 정책 · 레퍼런스 · 보상 · 가치 모델까지 최대 4개를 동시에 띄워야 해 메모리와 불안정성이 크고, 보상 모델의 허점(예: 긴 답변에 높은 점수)을 정책이 파고드는 reward hacking에 취약합니다.

심사위원 로봇(보상 모델)을 먼저 만들고, 학생 로봇이 그 심사위원 점수를 올리려고 연습해요. 그런데 심사위원이 "길게 쓰면 점수 잘 줌" 같은 버릇이 있으면 학생이 내용은 안 보고 그 버릇만 노려요. 이게 보상 해킹이에요.

CONCEPT 03 · week2_fm p.80–82

DPO (Direct Preference Optimization)

RLHF의 보상 모델을 닫힌 형태로 정책 비율에 흡수해, 선호 응답 y_w의 로그확률은 올리고 비선호 y_l은 내리는 분류 손실 하나로 학습합니다. β는 레퍼런스에서 얼마나 벗어나도 되는지를 조절합니다. 롤아웃 없이 고정 데이터셋으로 학습하므로 오프라인이고 정책 + 레퍼런스 2개 모델만 필요합니다. 안정성과 단순함 덕분에 업계 표준이 됐습니다.

L = −log σ( β [ log πθ(y_w|x)/π_ref(y_w|x) − log πθ(y_l|x)/π_ref(y_l|x) ] )

심사위원 로봇을 따로 만들지 않고, "이 답이 저 답보다 낫다"는 정답지를 보고 바로 공부해요. 준비물이 절반이라 빠르고 실수도 적어요.

CONCEPT 04 · week2_fm p.84

PPO와 가치 모델: 추론 RL의 출발점

PPO는 확률비 r = πθ/π_old를 클리핑해 한 번의 업데이트가 과도하지 않게 합니다. 가치 모델(critic)이 상태별 기대 리턴의 베이스라인을 제공하고 GAE로 어드밴티지 A를 계산합니다. 정책 · 레퍼런스 · 보상 · 가치 4개 모델과 반복 롤아웃이 필요해 비용이 크고, 하이퍼파라미터와 보상 모델 오류에 민감합니다. 이 비용이 GRPO가 등장한 이유입니다.

"지난번보다 얼마나 잘했나"를 재려면 기준점(가치 모델)이 필요하고, 한 번에 너무 크게 바꾸지 않도록 안전벨트(클리핑)를 매요. 기준점을 재는 로봇을 하나 더 키워야 해서 비싸요.

CONCEPT 05 · week2_fm p.85–89

GRPO (Group Relative Policy Optimization)

요약본의 "Group-wise Reward-based Policy Optimization"은 Group Relative Policy Optimization입니다 (DeepSeekMath 2024, DeepSeek-R1; 슬라이드 p.89 "Group-relative advantage"). 또 "롤아웃이 전부 실패하면 학습 불가"는 절반만 맞습니다. 그룹 내 분산이 0이면 되므로 전부 성공해도 어드밴티지는 0이고 학습 신호가 없습니다.

같은 프롬프트에 G개의 응답을 샘플링하고, 그룹 내 보상의 평균과 표준편차로 정규화한 상대 어드밴티지를 씁니다. 그러면 PPO의 가치(critic) 모델이 필요 없습니다. 확률비와 클리핑은 PPO와 같고, 수학 · 코딩처럼 정답 검증이 가능한 보상(RLVR)에 쓰입니다. 그룹 정규화 덕분에 쉬운 문제(대부분 성공)보다 어려운 문제에서 드물게 성공한 샘플이 큰 가중치를 받습니다.

Â_i = (r_i − mean(r₁..r_G)) / std(r₁..r_G)

같은 문제를 8번 풀어보고, 평균보다 잘한 풀이는 더 자주 하도록, 못한 풀이는 덜 하도록 고쳐요. 8번 다 틀리면(또는 다 맞으면) 비교할 게 없어서 아무것도 못 배워요. 아래 "직접 해보기"에서 확인하세요.

CONCEPT 06 · week2_fm p.90

OPD / OPSD (On-Policy (Self-)Distillation)

요약본의 "OPD/OPG (On-Policy Distillation/Generation)"에서 슬라이드 용어는 On-Policy (Self-)Distillation, OPSD입니다 (p.90). "OPG"라는 표기는 PDF에 없어 확인이 필요합니다.

학생 모델이 현재 정책으로 생성한 궤적의 각 prefix마다 교사(또는 더 강한 자기 버전)가 토큰 수준 감독을 제공합니다. 고정된 교사 데이터로 하는 오프라인 증류의 train–inference 분포 불일치를 줄이면서, GRPO의 최종 정답 기반 희소 보상 대신 모든 토큰에 조밀한(dense) 신호를 줍니다. 단점은 강한 교사 모델에 의존한다는 점입니다.

내가 푼 풀이를 한 줄 한 줄 선생님이 "여기선 이렇게 쓰는 게 맞아"라고 바로잡아 줘요. 맨 끝 정답만 채점받는 것보다 어디서 틀렸는지 훨씬 잘 알아요. 대신 좋은 선생님이 꼭 있어야 해요.

CONCEPT 07 · week4_agent p.85–88

롱 호라이즌 RL의 문제 1: 보상 희소성 (T1)

300스텝짜리 터미널 과제에서 "전부 성공이면 1, 아니면 0" 보상은 초반에 거의 항상 0이라, 거의 다 한 궤적과 아무것도 못 한 궤적이 동일하게 취급됩니다. T1(Terminal Agent Reinforcement Learning for Long-Horizon Tasks)은 verifier로 요구사항 몇 개를 만족했는지를 부분 보상으로 주고(dense reward), SFT/warm start로 긴 과제를 어느 정도 수행할 초기 능력을 먼저 만듭니다.

100문제 시험에서 "만점 아니면 0점"이면 아무도 실력이 늘지 않아요. 맞힌 개수만큼 점수를 주면 조금씩 나아져요.

CONCEPT 08 · week4_agent p.87–88

롱 호라이즌 RL의 문제 2: 추론-학습 불일치 (TITO, R3)

요약본의 "추론 엔진(vLLM, SGLang) vs 학습 프레임워크(Transformers)"는 일반론으로는 맞지만, 슬라이드의 T1 설정은 롤아웃 SGLang, 학습 Megatron-Core + Transformer Engine입니다 (p.87). "토큰 ID와 MoE 전문가 인덱스를 저장"의 고유명사는 TITO(Token In, Token Out)와 R3이며 출처는 T1 논문입니다 (p.88).

롤아웃은 고속 추론 엔진으로, 학습은 별도 학습 프레임워크로 하므로 같은 모델이라도 선택되는 토큰과 MoE 전문가가 달라질 수 있습니다. 토큰을 텍스트로 디코딩했다가 재인코딩하면 encode(decode(ids)) ≠ ids가 생깁니다(반대로 decode(encode(text)) = text는 항상 성립). T1의 TITO는 롤아웃의 토큰 ID 자체를 학습에 재사용하고, R3는 롤아웃 때의 MoE 전문가 인덱스를 저장해 학습 때 그대로 씁니다.

연습 때 쓴 공책을 복사기로 복사했다가 다시 베끼면 글자가 바뀔 수 있어요. 원본 공책(토큰 ID)을 그대로 쓰면 안 바뀌어요. 2주차에서 배운 MoE의 "전문의 배정"도 연습 때와 시험 때 같은 의사로 맞춰 줘야 해요.

CONCEPT 09 · week4_agent p.89–93

하네스 설계와 MEA (Manage–Execute–Audit)

모델 바깥에서 "어떻게 일을 나누고 검사하고 다시 고치게 할지"를 통제하는 시스템이 하네스입니다. Anthropic은 Planner → Generator → Evaluator 구조와 Sprint Contract(코딩 전 생성자와 평가자가 acceptance criteria에 합의하고 파일로 소통)로 단일 에이전트 20분짜리 결과를 풀 하네스 6시간의 완성도 높은 결과로 바꿨고, 이후 더 강한 모델이 나오자 스프린트 구조를 제거했습니다. LongHorizon-Harness의 MEA는 Executor의 "완료했다"를 믿지 않고 read-only Auditor가 환경을 검사해야만 task state에 completed를 기록합니다. 8주차의 본 주제이기도 합니다.

혼자 숙제하면 "다 했다"고 착각하기 쉬워요. 계획 짜는 사람, 하는 사람, 검사하는 사람을 나누고, 검사를 통과한 것만 "완료" 도장을 찍어요.

CONCEPT 10 · 요약본 기반 (PDF 없음)

블랙박스 모델 튜닝 (Agentic Monte Carlo)

"Agentic Monte Carlo"라는 명칭은 어느 PDF에서도 찾지 못했습니다. 수업 구두 설명으로 보이며 정확한 논문명과 출처 확인이 필요합니다. 아래 설명은 요약본 기준입니다.

API로만 접근 가능한 모델(GPT, Claude)은 가중치를 바꿀 수 없습니다. 대신 생성 과정의 중간 상태를 평가하는 가치 모델을 두고, 가치가 높은 중간 상태에서 탐색을 분기해 재시도하면 처음부터 전부 다시 하는 것보다 효율적으로 성공률을 높입니다. 6주차의 트리 탐색과 같은 아이디어를 "학습 없는 튜닝"에 적용한 것입니다.

미로에서 막히면 입구로 돌아가지 말고, "여기까진 잘 왔다"고 표시된 갈림길로 돌아가서 다른 길을 시도해요. AI 자체를 고칠 수 없을 때 쓰는 방법이에요.

5. 시험 포인트

  • 학습 단계 순서와 각 단계에 필요한 데이터·모델 (pt, cpt, SFT/IFT, PFT, RFT)
  • RLHF의 구성 요소 4개(policy · reference · reward · value)와 두 가지 약점(복잡성·불안정, reward hacking)
  • DPO가 RLHF와 다른 점: 보상 모델 제거, 오프라인, 2개 모델, β의 역할
  • PPO의 가치 모델 역할(베이스라인 · GAE) vs GRPO의 그룹 정규화 어드밴티지(critic 제거)
  • GRPO가 어려운 문제에 가중치를 더 주는 이유. 전부 성공/전부 실패 시 학습 신호 0
  • OPD가 GRPO의 희소 보상을 보완하는 방식(토큰 수준 dense 감독, on-policy)과 교사 의존성
  • 추론-학습 불일치의 두 원인(토큰 재인코딩, MoE 전문가 선택)과 해결(TITO, R3)
  • 롱 호라이즌 보상 희소성 해결(verifier 부분 보상), 생성자-평가자 분리 이유, MEA에서 Auditor의 역할

예상 문제

Q1. DPO가 RLHF보다 안정적이라고 평가되는 이유를 필요한 모델 수와 학습 방식 관점에서 설명하라.
RLHF는 보상 모델을 별도 학습하고 정책·레퍼런스·보상·가치 모델을 동시에 띄워 온라인 롤아웃으로 학습하므로 복잡하고, 보상 모델 오류를 정책이 악용(reward hacking)할 수 있다. DPO는 보상 모델을 손실식에 흡수해 선호 쌍 데이터로 정책·레퍼런스 2개 모델만으로 오프라인 학습하므로 단순하고 안정적이다.
Q2. GRPO에서 8개 응답의 보상이 [1,0,0,0,0,0,0,0]인 경우와 [1,1,1,1,1,1,1,0]인 경우 성공 응답의 어드밴티지는 어떻게 다른가? 전부 0이면?
Â = (r − μ)/σ. 첫 경우 μ = 0.125, σ ≈ 0.33 → 성공 응답 ≈ +2.65(큰 양수). 둘째 경우 μ = 0.875, σ ≈ 0.33 → 성공 응답 ≈ +0.38(작은 양수). 어려운 문제의 드문 성공이 훨씬 강하게 강화된다. 전부 0이면 σ = 0이라 모든 어드밴티지가 0, 학습 신호가 없다. 위 시뮬레이터에서 p를 0.15와 0.9로 바꿔 확인해 보라.
Q3. OPD(On-Policy Distillation)가 해결하는 문제 두 가지와 한계 하나를 쓰라.
(1) GRPO의 최종 정답 기반 희소 보상 → 교사의 토큰 수준 dense 감독. (2) 오프라인 증류의 train–inference 분포 불일치 → 학생이 실제 방문하는 상태에서 감독. 한계: 강한 교사 모델에 의존한다.
Q4. 롤아웃 엔진과 학습 프레임워크가 달라서 생기는 불일치 두 가지와 T1의 해결책을 쓰라.
(1) 토큰을 텍스트로 디코딩 후 재인코딩하면 encode(decode(ids)) ≠ ids → TITO: 롤아웃의 토큰 ID를 그대로 학습에 사용. (2) MoE 전문가 선택이 엔진마다 달라짐 → R3: 롤아웃 시 전문가 인덱스를 저장해 학습에 재사용.
Q5. Anthropic 하네스 실험에서 Generator와 Evaluator를 분리한 이유와, MEA에서 "완료"가 기록되는 조건을 쓰라.
에이전트는 자기 결과를 과대평가하고 긴 컨텍스트에서 목표를 잊거나(context anxiety) 일찍 끝내려 하므로, 만드는 역할과 평가 역할을 분리했다. MEA에서는 Executor가 완료했다고 말해도 인정하지 않고, read-only Auditor가 실제 환경을 검사해 확인해야만 task state에 completed가 기록된다.
