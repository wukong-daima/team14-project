# 나쁜 문제 사례 (검증 기준)

9주차 수업: "나중에 벤치마크 만들 생각 말고 처음부터 실패 사례 20~50개를 모아라." 이 목록이 quiz-verifier의 판정 기준이자 회귀 테스트다. **사람이 검토하다 고치거나 버린 문제는 여기에 사례로 추가한다.**

판정: `drop` = 버림, `fix` = 고치면 살릴 수 있음.

## A. 내용이 틀림 (가장 심각)
| 코드 | 실패 | 예 | 판정 |
|---|---|---|---|
| F01 | 정답이 원문과 다르다 | 원문은 "AFlow가 MCTS"인데 "ADAS가 MCTS"를 정답으로 | drop 또는 fix |
| F02 | 원문에 없는 수치·이름·연도를 지어냈다 | "ACE는 2024년 OpenAI가 발표" (원문에 없음) | drop |
| F03 | 음성 인식 오류 표기를 그대로 썼다 | "MetaNIS", "CR 알고리즘" (원문: Meta-Harness, SIA 추정) | fix |
| F04 | "확인 필요" 항목을 사실처럼 출제했다 | 이름이 불확실한 벤치마크를 정답으로 | drop |
| F05 | 구두 언급을 슬라이드 내용처럼 단정했다 | "슬라이드에 따르면 ARC-AGI-3 비용은…" (구두 언급) | fix |
| F06 | 해설이 정답과 모순된다 | 정답 ②인데 해설은 ③을 설명 | fix |
| F07 | 근거 인용이 원문에 없거나 다른 내용이다 | quote가 원문 문장이 아닌 요약·창작 | fix |

## B. 채점을 믿을 수 없음
| 코드 | 실패 | 예 | 판정 |
|---|---|---|---|
| F10 | 정답이 둘 이상 가능하다 | 두 보기가 모두 원문과 맞음 | fix |
| F11 | 정답이 없다 | 네 보기 모두 조금씩 틀림 | fix |
| F12 | 조건이 빠져 답이 하나로 안 정해진다 | "pass@k를 구하라" (p, k 없음) | fix |
| F13 | 숫자 답의 반올림·단위가 문제에 없다 | "0.651"과 "65.1%" 중 무엇인지 모름 | fix |
| F14 | 서술형인데 채점 기준이 없다 | 모범 답안이 "여러 방향이 가능" | fix |

## C. 문제가 정답을 흘림 (리워드 해킹의 출제판)
| 코드 | 실패 | 예 | 판정 |
|---|---|---|---|
| F20 | 문제 문장에 정답 핵심어가 그대로 있다 | "다양성을 지키는 MAP-Elites는 무엇을 지키나?" | fix |
| F21 | 정답 보기만 유난히 길거나 구체적이다 | 오답 셋은 한 단어, 정답만 두 줄 | fix |
| F22 | 오답이 말이 안 돼 소거법으로 풀린다 | "AFlow는 요리 레시피 앱이다" | fix |
| F23 | 같은 묶음의 다른 문제가 답을 알려준다 | 앞 문제 해설이 뒤 문제 정답 | fix |
