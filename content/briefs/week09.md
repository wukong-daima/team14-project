## 핵심 개념

### 1. 자가 진화 루프의 3대 연구 문제 (구두)
- **(a) 전공:** 자가 진화는 "생성 → 평가(리워드) → 피드백"을 반복한다. 연구 문제는 리워드 상태에 따라 셋으로 나뉜다. ① **리워드가 정확할 때**: 정답 판정이 확실해도 일반화되는 루프를 만드는 것 자체가 어렵다(8주차 O/T/G 분해 참고). ② **리워드가 부정확할 때 — 보정**: 비싼 정답 판정(예: DFT) 대신 뉴럴 네트워크 포텐셜 같은 근사 모델을 리워드로 쓰면, 근사 오차가 루프를 엉뚱한 방향으로 끌고 간다. 이 오차를 어떻게 보정할지가 문제다. ③ **리워드가 부정확할 때 — 시뮬레이터 개선**: 리워드 자체를 더 정확하게 만든다. 바이오의 **Virtual Cell**(약물 투여 시 세포 반응 시뮬레이터), 재료 물성 시뮬레이터 스타트업 사례가 예시다.
- **(b) 중학생:** 스스로 실력을 키우는 AI는 "채점표"를 보고 배운다. 채점표가 정확해도 잘 배우게 만드는 건 어렵다. 채점표가 엉터리면 엉터리를 배우니, 채점 실수를 감안해서 배우게 하거나 아예 더 좋은 채점표를 만들어야 한다.
- **(c) 키워드:** accurate reward / inaccurate reward correction / simulator, DFT, VASP, neural network potential, Virtual Cell
- **(d) 페이지:** 구두

### 2. 사례: LLM 재료 생성과 DFT 대체 (구두)
- **(a) 전공:** LLM이 "밴드갭 X 이상인 물질"의 구조를 생성 → 물성 예측 → 미달이면 피드백해 다시 생성하는 자가 진화 루프. 물성 판정은 실험 합성이 정확하지만 불가능하므로 **DFT**(밀도범함수이론, VASP 등)를 쓴다. DFT는 복잡한 분자에서 매우 느리고 비싸며(구두: 학교 라이선스도 큰 비용), 부정확할 때도 있어 루프를 실시간으로 많이 돌릴 수 없다. 그래서 뉴럴 네트워크 포텐셜로 대체하지만 이것은 더 부정확한 경우가 많다 → 개념 1의 ②번 문제.
- **(b) 중학생:** 새 재료를 만드는 AI가 "이 재료 쓸 만해?"를 물어볼 때, 진짜 실험은 못 하고 컴퓨터 계산(DFT)은 너무 오래 걸린다. 빠른 AI 채점기를 쓰면 빠르지만 자주 틀린다.
- **(c) 키워드:** band gap, DFT, VASP, neural network potential, feedback loop
- **(d) 페이지:** 구두

### 3. 컨텍스트 엔지니어링 복습과 "모델 내부"로 가는 흐름
- **(a) 전공:** 복습: **ACE**는 Generator → Reflector → Curator로 플레이북을 **델타(변경분)로만** 갱신해 컨텍스트 붕괴를 막는다. **MCE**는 컨텍스트 내용뿐 아니라 컨텍스트를 만드는 방법(검색·구성 방식, 스킬)까지 최적화한다. **Meta-Harness**는 여러 초기 하네스(Zero-shot, Few-shot, ACE, MCE 등)의 **성능과 비용**을 재고 우수한 것만 남겨 새 하네스를 제안한다. 이때 하네스는 진화하지만 하네스를 제안하는 에이전트 자체는 최적화되지 않는다(그것까지 하는 것이 Hyperagents, 8주차 개념 8). **새 강조(구두):** 지금의 하네스 엔지니어링은 모델이 **토큰으로 내보낸 CoT**를 Reflector가 읽고 반성하는 방식인데, 모델이 출력한 생각과 내부 연산은 다를 수 있다(예: "A를 생각하지 마"라고 하면 출력에는 A가 없어도 내부 활성화에는 A 관련 신호가 있다). 그래서 **hidden state를 직접 분석**해 하네스에 활용하는 방향(Goodfire 등)이 떠오르고 있다.
- **(b) 중학생:** 지금은 AI가 "말로 쓴 풀이"를 보고 고쳐준다. 그런데 말로 쓴 풀이와 머릿속 생각이 다를 수 있다. 그래서 앞으로는 AI의 머릿속(내부 신호)을 직접 들여다보고 고쳐주는 방법이 연구되고 있다.
- **(c) 키워드:** ACE(델타 업데이트), MCE, Meta-Harness(성능·비용 파레토), CoT ≠ 내부 연산, hidden state, mechanistic interpretability, Goodfire
- **(d) 페이지:** p.21~25 + 구두

### 4. 워크플로우 디자인 복습: ADAS와 AFlow
- **(a) 전공:** 워크플로우 디자인 = 모델·도구·아티팩트의 **호출 순서와 구성**을 최적화하는 것. **ADAS**는 태스크를 어떻게 분해하고, 어떤 순서로 어떤 LLM에 넣고, 답을 어떻게 종합할지를 메타 에이전트가 설계한다(meta-agent search). 가능한 조합이 무수히 많으므로 **AFlow**는 워크플로우를 트리로 보고 **MCTS**로 가장 그럴듯한 가지에 투자하면서 덜 탐색한 가지도 탐색한다(exploration–exploitation 균형).
- **(b) 중학생:** "누구에게 어떤 순서로 일을 시킬까"를 정하는 게 워크플로우다. 경우의 수가 너무 많아서, 바둑 AI처럼 좋아 보이는 수를 더 깊이 보되 안 가본 수도 가끔 시도해본다.
- **(c) 키워드:** ADAS(meta-agent search), AFlow(MCTS), exploration vs exploitation
- **(d) 페이지:** p.26~29

### 5. 자기개선 하네스: 아티팩트를 만드는 능력과 받아먹는 능력
- **(a) 전공:** 아티팩트 = 스킬, 메모리, 프롬프트처럼 하네스가 만들어 쌓는 산출물. **교사–학생 설정**: GPT 같은 교사 모델로 만든 아티팩트를 Qwen 같은 학생 모델에 그대로 넣으면 교사에 특화돼 있어 잘 활용하지 못한다 → 학생도 잘 쓰도록 아티팩트를 갱신하는 연구(구두: "아티팩트 증류"). **학생만 있는 설정**: 자기 자신만으로 개선한다(STOP, Self-Harness 등). 성능을 좌우하는 것은 **아티팩트를 만드는 능력**과 **아티팩트를 받아먹는 능력** 두 가지다. 구두 설명에 따르면 약한 모델은 좋은 아티팩트를 잘 못 만들고, 최상위 모델은 이미 아는 내용이라 이득이 작으며, **중간 티어 모델이 가장 크게 오른다**. 주의: 결론(중간 티어 최대 이득)은 Lin et al. 2026(8주차 개념 7, p.34)과 같지만 **이유는 다르다**. Lin et al.은 아티팩트를 만드는 능력(harness-updating)이 모델 티어 간 **대체로 평평**하고, 갱신된 하네스를 활용하는 능력(harness-benefit)이 비단조적이라 중간 티어가 가장 이득을 본다고 보고했다. "약한 모델은 좋은 아티팩트를 못 만든다"는 구두 설명이며 슬라이드의 Lin et al. 결과와는 맞지 않으므로, 문제로 낼 때 두 출처를 섞지 않는다. 또 **어떤 하네스 요소가 성능을 올렸는지 모른다**는 문제가 있다: MCE를 돌리면 마크다운 컨텍스트가 엄청나게 쌓이지만 그중 무엇이 효과였는지 알 수 없다. 학습 데이터에서는 데이터 기여도 평가(100개 중 방해되는 데이터를 빼면 90→95가 아니라 97이 될 수 있음) 연구가 많지만, 하네스 요소에 대한 기여도 분석은 아직 적다(구두).
- **(b) 중학생:** 1등 학생의 요약 노트를 다른 학생에게 주면 그대로는 잘 안 맞는다. 노트를 잘 만드는 능력과 남의 노트를 잘 써먹는 능력이 둘 다 필요하다. 또 노트가 너무 두꺼워지면 어느 페이지 덕분에 성적이 올랐는지 알 수 없다.
- **(c) 키워드:** artifact(skill·memory·prompt), teacher–student artifact transfer, artifact 생성 능력 vs 활용 능력, 중간 티어 최대 이득, 하네스 요소 기여도(ablation)
- **(d) 페이지:** p.31~38 + 구두

### 6. 진화 탐색과 다양성: MAP-Elites, Island 진화 (이번 수업 핵심)
- **(a) 전공:** 하네스 탐색 공간이 너무 커서 진화 알고리즘을 많이 쓴다(p.39). **AlphaEvolve**: 전략(프로그램)을 **변이(mutation)** 하거나 두 전략을 **교차(crossover)** 해 새 전략을 만들고 좋은 것만 남긴다. **문제: 다양성 붕괴.** 인터넷에 논문이 많은 분야(예: 조합론)의 전략이 많이 생성되므로, 그대로 진화시키면 결국 조합론 전략 위주로 수렴한다. 해법은 **구역을 나눠 각각 진화**시키는 것: **MAP-Elites**(특성 공간의 칸마다 최고 성능 개체를 따로 보관), **Island 기반 진화**(여러 섬에서 독립적으로 진화). 정수론은 정수론끼리, 조합론은 조합론끼리 진화시키고 필요하면 나중에 섞는다. 교수 발언: 이 방법을 쓰고 안 쓰고가 실제 성능 차이를 크게 만든다. 관련: ShinkaEvolve 계열은 **UCB**로 유망한 전략과 덜 탐색한 전략의 균형을 잡는다(구두 "EvoX 계열" — 이름 확인 필요).
- **(b) 중학생:** 좋은 풀이법만 계속 베끼면 결국 다 비슷한 풀이법만 남는다. 그래서 "정수 문제 반", "도형 문제 반"처럼 반을 나눠 반마다 1등을 따로 키운다. 그래야 어떤 문제가 나와도 대응할 수 있다.
- **(c) 키워드:** mutation, crossover, diversity collapse, MAP-Elites, island-based evolution, UCB
- **(d) 페이지:** p.39~46 + 구두

### 7. 사례: 수학 문제 자가 생성 — 다양성이 핵심 (구두)
- **(a) 전공:** 솔버를 수학 문제에 강하게 만들려고 **에이전트가 가상의 수학 문제를 만들어** 학습 경험으로 주는 실험(합성 경험). 중요한 것 두 가지: ① **난이도**: 솔버가 너무 쉽게 풀거나 아예 못 푸는 문제는 도움이 안 된다(8주차 Autodata agent의 Weak/Strong Solver 기준과 같은 생각). ② **다양성**: 그냥 "문제 만들어줘"라고 하면 에이전트가 특정 분야 문제만 만든다(앞의 조합론 쏠림). 그래서 MAP-Elites처럼 **분야를 나눠**(정수론, 기하, 확률 등) 분야별로 문제를 생성하게 했다.
- **(b) 중학생:** AI에게 연습 문제를 내게 하면 자기가 좋아하는 유형만 낸다. 그래서 "정수 5문제, 도형 5문제"처럼 칸을 나눠주고, 너무 쉽지도 어렵지도 않은 문제만 남긴다.
- **(c) 키워드:** synthetic experience, challenger–solver, difficulty band, category-wise generation
- **(d) 페이지:** 구두 (p.27 Autodata agent와 연결)

### 8. 사례: 테이블 파운데이션 모델 자가 진화 (구두)
- **(a) 전공:** 테이블 파운데이션 모델(구두 "TabFM", 구글 계열이라고 언급)은 행 값을 받아 회귀·분류를 한다. 보통 텍스트나 코드를 입력으로 받지 못하고 **숫자 피처만** 받는다. 그래서 자가 진화로 바꿀 수 있는 것은 사실상 **피처**다: GPT가 예측 결과와 오차를 보고 새 피처를 제안 → 추가·삭제·전처리 → 다시 예측. 사례: 온열질환자 수 예측에서 GPT가 "만 65세 이상 인구 비율"을 제안해 성능이 올랐다. 여기서도 **다양성**이 중요하다: 인구 피처 10개, 기상 1개, 농업 5개처럼 쏠리므로 카테고리별로 나누고, 부족한 카테고리에서 더 많이 생성하게 한다. 시계열 파운데이션 모델(구글 TimesFM 계열, Mistral 쪽 모델 언급)도 같은 맥락으로 소개됐다.
- **(b) 중학생:** 숫자표만 읽는 AI에게 "어떤 칸을 더 넣으면 잘 맞출까?"를 다른 AI가 조언한다. 더위 환자 수를 맞출 때 "노인 비율" 칸을 넣자 훨씬 잘 맞았다. 조언도 한쪽으로만 쏠리지 않게 분야별로 나눠 받는다.
- **(c) 키워드:** tabular foundation model, feature engineering loop, 65세 이상 인구 비율, category-balanced feature generation
- **(d) 페이지:** 구두. 모델명 표기는 확인 필요

### 9. 경험(experience)의 세 가지 출처와 가중치 공동 최적화
- **(a) 전공:** 자가 진화는 경험으로 개선하는데, 경험은 ① 솔버가 직접 풀고 맞고 틀린 기록, ② 다른 에이전트가 만든 **합성 경험**, ③ 사람 전문가의 **데모**(DemoEvolve) 중 하나다. 하네스만 바꾸는 방식의 다음 단계는 **가중치와 하네스를 같이 최적화**하는 것으로, 하네스 개선과 파라미터 갱신을 번갈아 하며 무엇을 갱신할지 결정하는 별도 에이전트가 필요하다(SIA의 Feedback-Agent, p.47~48). 열린 문제: 새 지식을 넣을 때 **하네스만으로 가능한지, 가중치를 바꿔야 하는지**의 기준이 아직 없다.
- **(b) 중학생:** 실력은 내가 푼 문제, 남이 만들어준 연습 문제, 선생님 시범으로 늡니다. 공부법만 바꿀지 머리를 훈련할지를 정해주는 코치도 필요한데, 언제 무엇을 해야 하는지는 아직 아무도 모른다.
- **(c) 키워드:** solver experience / synthetic experience / human demonstration, DemoEvolve, SIA(Feedback-Agent), 하네스 vs 가중치
- **(d) 페이지:** p.43, 47~50 + 구두

### 10. 리워드 해킹과 비싼 하네스
- **(a) 전공:** 주어진 태스크의 리워드를 최대화하는 루프를 계속 돌리면 그 태스크 점수는 어떻게든 오른다. 그러나 **리워드 해킹**이 많다: 최근 벤치마크 중 몇 가지 단순 규칙만 배워도 점수가 오르는 것이 있다(예: "이 결과는 더 개선될 수 있는가?"를 묻는 어려운 수학 객관식에서 거의 항상 "개선될 수 있다"가 정답 — 8주차 LiveMath 사례 p.58). 또 에이전트가 실수나 오류로 좋은 점수를 얻으면 그것을 대단한 발견으로 착각해 그쪽으로만 탐색이 쏠린다(8주차 eureka-ing). 비용 문제(구두): ARC-AGI-3에서 97.6% → 99.6%로 올리는 데 하네스 비용만 약 2만 5천 달러가 들었다.
- **(b) 중학생:** 시험 점수만 올리게 하면 AI가 "정답은 대부분 3번" 같은 꼼수를 배운다. 실수로 맞은 걸 실력으로 착각하기도 한다. 그리고 마지막 2점을 올리는 데 수천만 원이 들기도 한다.
- **(c) 키워드:** reward hacking, shortcut, eureka-ing, ARC-AGI-3, 하네스 비용
- **(d) 페이지:** p.51~66 + 구두

### 11. 에이전트 검증 가이드 (Anthropic) — 처음부터 데이터셋을 만들어라
- **(a) 전공:** 에이전트 평가·검증에는 아직 표준 규정이 없고, Anthropic이 경험(lessons learned)을 공개하며 갱신하고 있다. 교수가 강조한 네 가지: ① **나중에 벤치마크를 만들 생각 말고 처음부터** 실패 사례 **20~50개**를 수작업으로 모아라(나중에 합성으로 늘리면 된다). ② 이미 손으로 테스트하던 것부터 테스트셋으로 만든다. ③ 테스트셋을 늘릴 때는 LLM 판정보다 **기계적으로 정답을 검증할 수 있는** 문제로 만든다. ④ 검증 데이터는 개발자뿐 아니라 **실제로 운영·사용할 사람**이 만들고 검토해야 한다.
- **(b) 중학생:** AI 시험지는 나중에 한꺼번에 만들지 말고, AI가 틀린 문제 20~50개를 처음부터 모아둔다. 채점은 사람 느낌이 아니라 정답표로 바로 맞는지 확인할 수 있게 만들고, 실제로 쓸 사람이 같이 검토한다.
- **(c) 키워드:** 20~50 failure cases, manual test → eval task, deterministic grader, 사용자 참여 검증
- **(d) 페이지:** p.86~88 (0→1 로드맵 0~2단계) + 구두

### 12. pass@k와 pass^k — 문제가 망가졌는지 확인하기
- **(a) 전공:** LLM 출력은 샘플링마다 달라서 한 번의 실행으로 판단하면 안 된다. **pass@k** = k번 실행 중 **한 번이라도** 성공할 확률. 한 번 성공 확률이 p이면 pass@k = 1 − (1 − p)^k (n번 실행해 c번 성공했을 때의 불편 추정량은 1 − C(n−c, k)/C(n, k)). **pass^k**(pass-hat-k) = k번 **모두** 성공할 확률 = p^k. k가 커지면 pass@k는 오르고 pass^k는 내려간다. 100번 실행해 두면 k = 1~100의 두 곡선을 모두 그릴 수 있다. 활용: 프론티어 모델(GPT·Claude)의 pass@1이 10~20%로 낮게 나오면 대개 모델이 아니라 **데이터셋 문제**다. "진짜 어려운 문제"라고 생각되면 **pass@k**(k = 10, 50)를 본다. pass@k조차 낮으면 문제를 잘못 만든 것이니 다시 만든다(8주차 p.86: 프론티어 모델에서 pass@100 = 0%면 대개 과제 결함).
- **(b) 중학생:** 주사위 같은 AI에게 같은 문제를 10번 풀게 한다. 한 번이라도 맞히면 "pass@10 성공"이다. 엄청 똑똑한 AI가 50번 중 한 번도 못 맞히면, 문제가 이상하게 만들어졌을 가능성이 크다.
- **(c) 키워드:** pass@k, pass^k, 1 − (1 − p)^k, p^k, unbiased estimator, broken task signal
- **(d) 페이지:** p.86 + 구두(Q&A)

### 13. 열린 문제: 모델이 바뀌면 하네스를 재활용할 수 있나 (Q&A)
- **(a) 전공:** 비싼 돈을 들여 만든 하네스를 모델 버전이 바뀔 때(구두 예: GPT-6 → GPT-7) 그대로 쓸 수 있는지는 **열린 연구 문제**다. 작은 버전 차이면 재활용이 되지만 큰 버전 변화는 대개 기존 스킬 등을 버리고 다시 짠다. 하네스 평가 한 번에도 큰 비용이 드는데 재구성 비용은 더 크므로, 하네스 재활용은 좋은 연구 주제로 소개됐다.
- **(b) 중학생:** 옛날 휴대폰에 맞춘 앱 설정을 새 휴대폰에 그대로 옮길 수 있을까? 조금 바뀐 모델이면 되지만 많이 바뀌면 다시 만들어야 한다. 이걸 싸게 옮기는 방법은 아직 없다.
- **(c) 키워드:** harness transfer across model versions, open problem
- **(d) 페이지:** 구두

## 추천 인터랙션

### 대표 ★: "pass@k vs pass^k 실험실 — 이 문제, 망가졌을까?" — 난이도 하
- **조작:** 한 번 성공 확률 p 슬라이더(0~100%), k 슬라이더(1~100), "모델이 100번 풀기" 버튼(결정적 난수 `T14.rand`로 100개 시도 결과를 점으로 표시).
- **표시:** k에 따른 두 곡선(pass@k는 위로, pass^k는 아래로), 현재 k의 두 값, 100번 실행에서 센 c로 계산한 불편 추정량.
- **판정 배지:** "프론티어 모델" 프리셋에서 pass@50이 5% 미만이면 "⚠ 문제 결함 의심 — 문제를 다시 만들어라" 배지. 사례 버튼 3개: 정상 문제(p = 0.6), 진짜 어려운 문제(p = 0.05 → pass@50 ≈ 92%), 망가진 문제(p = 0 → 항상 0%).
- **배우는 것:** 개념 12와 11. 계산이 결정적이라 예상 문제와 바로 연결된다.

### 대안 1: "다양성 붕괴 vs MAP-Elites 문제 생성기" — 난이도 중
- 4×3 격자(분야: 정수론·조합론·기하·확률 × 난이도: 쉬움·적당·어려움). "그냥 생성" 모드는 논문이 많은 분야(조합론)에 가중치를 둔 난수로 문제 점이 한쪽에 몰리고, "MAP-Elites" 모드는 칸마다 최고 점수 개체만 남겨 격자가 고르게 채워진다. 세대 슬라이더와 "커버리지 %" 표시. 개념 6·7.

### 대안 2: "리워드가 부정확하면 루프는 어디로 가나" — 난이도 중
- 1차원 물성 지형(진짜 리워드 곡선)과 노이즈 섞인 근사 리워드(뉴럴 네트워크 포텐셜) 곡선. 노이즈 크기 슬라이더, "진화 10세대" 버튼. 근사 리워드를 따라간 개체가 진짜 최적점에서 벗어나는 모습을 보여주고, "보정" 토글(여러 근사 모델 평균 또는 가끔 진짜 판정)로 다시 돌아오게 한다. 개념 1·2.

## 다이어그램 후보 (정적 SVG)

1. **자가 진화 3대 문제 갈림길:** 리워드 정확? → 예: 일반화 루프 설계 / 아니오: ② 보정 or ③ 시뮬레이터 개선(Virtual Cell, 재료 시뮬레이터 아이콘).
2. **경험의 세 출처:** 솔버 자신의 시행착오 · 다른 에이전트의 합성 문제 · 사람 데모 → 가운데 "하네스 / 가중치" 두 상자, 그 사이에 "무엇을 갱신할지 정하는 Feedback-Agent".
3. **CoT 바깥 vs 모델 내부:** 왼쪽 "토큰으로 나온 생각 → Reflector", 오른쪽 "hidden state → 해석 도구 → 하네스". 가운데 "≠".
4. **pass@k / pass^k 곡선 정적 그림:** 대표 인터랙션이 무거우면 이 그림으로 대체.

## 예상 문제

**Q1. (계산)** 어떤 에이전트가 한 문제를 한 번 풀 때 성공 확률이 p = 0.1이다. (a) pass@10, (b) pass^10을 구하라. (c) k가 커질 때 두 값은 각각 어떻게 변하는가?
- **정답:** (a) 1 − 0.9^10 ≈ 1 − 0.349 = **0.651**. (b) 0.1^10 = **10⁻¹⁰**. (c) pass@k는 1에 가까워지며 증가하고, pass^k는 0에 가까워지며 감소한다.

**Q2. (서술)** 프론티어 모델로 직접 만든 벤치마크를 돌렸더니 pass@1이 12%였다. 교수가 제시한 순서대로 무엇을 확인해야 하는지 쓰고, 어떤 결과가 나오면 문제를 다시 만들어야 하는지 쓰라.
- **정답:** 프론티어 모델의 pass@1이 낮으면 먼저 모델이 아니라 데이터셋 문제를 의심한다. 진짜 어려운 문제인지 보려면 같은 문제를 여러 번(k = 10, 50 등) 실행해 pass@k를 본다. pass@k조차 낮으면(예: pass@100 = 0%) 문제 설계가 잘못됐다는 신호이므로 문제를 다시 만든다. 가능하면 기계적으로 정답을 검증할 수 있는 형태로 만든다.

**Q3. (서술)** AlphaEvolve 방식으로 수학 문제 풀이 전략을 진화시켰더니 조합론 전략만 남았다. 왜 이런 일이 생기는지 설명하고, 이를 막는 두 가지 방법을 쓰라.
- **정답:** 생성하는 LLM이 학습한 자료(논문)가 분야마다 양이 달라, 자료가 많은 조합론 쪽 전략이 많이 생성되고 변이·교차로도 그쪽으로 수렴하기 때문이다(다양성 붕괴). **MAP-Elites**(특성 공간의 칸마다 최고 개체를 따로 유지)와 **Island 기반 진화**(독립된 여러 집단에서 각각 진화)로 분야를 나눠 각각 진화시키고, 필요하면 나중에 합친다.

**Q4. (서술)** LLM이 새 물질을 만들고 뉴럴 네트워크 포텐셜로 물성을 예측해 리워드로 쓰는 자가 진화 루프를 만들었다. 이 설계의 문제점과, 수업에서 제시한 두 가지 대응 방향을 쓰라.
- **정답:** DFT보다 빠르지만 근사 모델이라 리워드가 부정확하다. 루프가 근사 오차를 최대화하는 쪽(진짜 물성은 나쁜 물질)으로 갈 수 있다. 대응은 ① 부정확한 리워드를 **보정**해 루프를 안정시키는 것, ② 리워드 자체를 정확하게 만드는 **시뮬레이터 개선**(예: Virtual Cell, 물성 시뮬레이터)이다.

**Q5. (객관식)** Anthropic의 에이전트 검증 가이드로 수업에서 소개된 내용이 **아닌** 것은?
① 처음부터 실패 사례 20~50개를 수작업으로 모은다
② 테스트셋을 늘릴 때는 기계적으로 정답을 검증할 수 있는 문제를 우선한다
③ 벤치마크 데이터는 충분히 쌓인 뒤 한 번에 만드는 것이 효율적이다
④ 실제로 운영하고 사용할 사람이 검증에 참여해야 한다
- **정답: ③.** "나중에 벤치마크 만들 생각 말고 처음부터 만들어라"가 핵심이다.

**Q6. (서술)** GPT로 만든 스킬·메모리(아티팩트)를 Qwen 에이전트에 그대로 넣었더니 성능이 기대만큼 오르지 않았다. 이유를 설명하고, 자기개선 하네스의 성능을 좌우하는 두 능력을 쓰라.
- **정답:** 아티팩트가 교사(GPT)에 맞춰 만들어져 학생(Qwen)이 잘 활용하지 못하기 때문이다. 그래서 학생이 쓸 수 있게 아티팩트를 갱신하는 연구가 진행 중이다. 두 능력은 **아티팩트를 만드는 능력**과 **아티팩트를 받아먹는(활용하는) 능력**이다. 구두 설명에서는 중간 티어 모델이 가장 큰 이득을 봤다.
