KV 캐시 압축과 DeepSeek-V4.1-Flash

긴 컨텍스트 시대의 병목은 가중치가 아니라 KV 캐시입니다. DeepSeek-V4.1-Flash는 "더 작게 저장(FP4) · 덜 저장(CSA2 압축) · 레이어 간 공유(cross-layer reuse) · 오래 들고 있지 않기(Bounded Replay) · 인코더만으로 prefill(CED)"을 한 아키텍처에 묶어 100만 토큰의 글로벌 KV를 약 0.89GB로 줄였습니다. 후반부의 Perceiver는 입력 길이 M과 무관한 고정 크기 latent N으로 어떤 모달리티든 O(MN)에 읽는 구조입니다.

AI가 아주 긴 글을 읽으려면 "읽은 내용 메모(KV 캐시)"가 산더미처럼 쌓여요. 이번 주는 그 메모를 작게 쓰고, 합치고, 돌려 쓰고, 오래된 건 버리는 다섯 가지 정리법으로 100만 단어 분량 메모를 1GB 아래로 줄인 모델 이야기예요.

2. 핵심 개념

CONCEPT 01 · p.4

KV 캐시 압축의 4대 전략

긴 컨텍스트 추론에서 메모리를 지배하는 것은 모델 가중치가 아니라 토큰마다 쌓이는 KV 캐시입니다. V4.1-Flash는 이를 네 축으로 공략합니다. ① 각 엔트리를 더 작게 저장(FP4), ② 저장할 엔트리 수를 줄임(CSA2 compression), ③ 레이어마다 별도 KV 캐시를 두지 않음(CSA2 cross-layer reuse), ④ SWA KV를 오래 보관하지 않음(Bounded Replay). 여기에 CED가 prefill 연산 자체를 절반으로 줄입니다. 2주차의 GQA·MLA가 "헤드 수"를 줄였다면, 이번 주는 비트 수·엔트리 수·레이어 수·보관 기간을 동시에 줄입니다.

책상 위에 메모지를 쌓아둔다고 생각해요. 메모를 더 작은 글씨로 쓰고(FP4), 두 장을 한 장으로 합치고(압축), 같은 메모를 서랍마다 복사하지 않고(공유), 최근 메모 몇 장만 남기고 버리는(Bounded Replay) 네 가지 정리법이에요.

CONCEPT 02 · p.5

DeepSeek-V4.1-Flash 구조 수치

요약본의 "DeepSeek-V2 (Flash)"는 DeepSeek-V4.1-Flash입니다(논문 "DeepSeek-V4.1-Flash: Pushing the Limits of KV Cache Compression", arXiv 2026, p.2·4~13). 또 요약본의 "DSA (DeepSpeed Sparse Attention)"는 2주차 PDF 기준 DeepSeek Sparse Attention이며, 3주차 PDF는 DSA 대신 CSA2(희소 선택 512 토큰) 용어를 씁니다.

40개의 causal Transformer 레이어 = 20 Causal Encoder + 20 Causal Decoder. 백본 파라미터 552B, 별도 Engram 파라미터 196B. 토큰당 활성 파라미터는 prefill 시 8B(인코더만), decoding 시 16B(인코더+디코더). 첫 두 레이어는 SWA만(윈도우 128), 나머지는 CSA2+SWA. 희소 어텐션이 고르는 토큰 수는 512. 프롬프트는 인코더로만 처리(prefill)되고, 생성 토큰은 인코더→디코더 파이프라인을 다시 통과합니다.

40층 건물인데 아래 20층은 "읽기 전담(인코더)", 위 20층은 "쓰기 전담(디코더)"이에요. 긴 질문을 읽을 땐 아래 20층만 돌고, 답을 한 글자씩 쓸 때만 40층을 다 돌아요.

CONCEPT 03 · p.6

Engram: 학습된 거대 사전

요약본의 "바이그램·트라이그램 해시를 외부 메모리에 저장, O(1) 조회"는 PDF 문구에 없습니다. 슬라이드 표현은 "short local lexical pattern 자체를 memory address로 쓰는 massive learned dictionary"이며, 해시/O(1)/N-gram은 강의 구두 설명으로 보입니다(p.6). 또 "별도 외부 메모리"라기보다 레이어 1·14에 배치된 모듈이며 파라미터 196B입니다.

짧은 국소 어휘 패턴(short local lexical pattern) 자체를 메모리 주소로 쓰는 거대한 학습된 사전입니다. Transformer가 여러 레이어 연산을 거쳐 재구성해야 할 흔한 패턴을 빠른 조회(lookup)로 가져오므로, 본체는 장거리 문맥 이해에 연산을 집중할 수 있습니다. V4.1-Flash에서는 레이어 1과 14(0-indexed)에 Engram 모듈이 있고, 파라미터는 백본 552B와 별도로 196B입니다.

자주 쓰는 숙어는 머리로 매번 계산하지 않고 "숙어 사전"에서 바로 찾아보는 거예요. 본체는 어려운 긴 문맥 이해에만 집중할 수 있어요.

CONCEPT 04 · p.7–8

mHC (Manifold-Constrained Hyper-Connections) · Single-Pass mHC

요약본의 "Single-Pass MHC"는 Single-Pass mHC(소문자 m, Manifold-Constrained Hyper-Connections)입니다(p.7~8).

Residual connection은 1차선 고속도로입니다. Hyper-Connections(HC)는 n개의 residual stream을 병렬로 유지하고, 각 블록(attention/MoE) 입력 전에 관련 stream을 섞습니다. mHC는 이 섞는 매핑을 무제한으로 두지 않고 doubly stochastic matrix(행·열 합이 1)로 제약해 변환이 안정 범위에 머물게 합니다. Single-Pass mHC는 이 변환을 한 번의 패스로 효율적으로 구현한 것입니다. 2주차의 Pre-Norm이 "잔차 경로를 건드리지 않아 안정"이었다면, mHC는 "잔차 경로를 넓히되 규칙을 걸어 안정"입니다.

고속도로를 1차선에서 여러 차선으로 넓히되, 차선 변경 규칙을 정해서(한 차선이 다 빨려 들어가거나 텅 비지 않게) 교통이 꼬이지 않게 만든 거예요.

CONCEPT 05 · p.9–10

CED (Causal Encoder-Decoder)

요약본의 "CID"는 CED(Causal Encoder-Decoder)입니다. 또 "프롬프트는 인코더만 통과시켜 KV 캐시를 절반으로 줄임"은 부정확합니다. CED가 절반으로 줄이는 것은 prefill 연산량(N≫n_win일 때)이고, KV 캐시 크기 자체는 CSA2·FP4가 줄입니다(p.9~10).

"모든 입력 토큰을 모든 상위 레이어에 통과시켜야만 글로벌 KV를 만들 수 있는가?"에 대한 답입니다. CED는 각 디코더 레이어의 글로벌 K, V를 그 레이어의 hidden state가 아니라 인코더 최종 hidden state로부터 생성합니다(인코더의 K,V를 그대로 재사용하는 게 아니라 hidden state를 재료로 씀). 긴 입력은 대부분 20개 인코더 레이어만 통과하면 되므로 prefill 연산이 대략 절반입니다. 다만 디코더의 SWA(로컬) KV는 여전히 디코더 각 레이어의 hidden state에서 만들어야 하므로 Bounded Replay로 보완하고, CSA2 cross-layer sharing과 결합하면 인코더 유래 글로벌 KV를 여러 디코더 레이어가 공유합니다.

긴 책을 읽을 때 "읽기 담당(인코더)"이 요약 노트를 만들면, "쓰기 담당(디코더)"은 책을 처음부터 다시 읽지 않고 그 노트만 보고 글을 써요. 다만 마지막 몇 줄은 직접 읽어야 문맥이 이어져요(그게 Bounded Replay).

CONCEPT 06 · p.11

CSA2: 압축(m=2) + 레이어 간 공유(Full → Reuse → Reindex)

요약본의 "여러 레이어에 걸쳐 재사용(Reuse)·재인덱스(Re-index)"의 정확한 패턴은 Full → Reuse → Reuse → Reuse → Reindex입니다. 또 "최근 128개 토큰만 풀 어텐션"이 아니라 SWA(128)와 글로벌 희소 어텐션(Top-512)을 병행하며, 첫 2개 레이어만 SWA 전용입니다(p.5, 11).

압축: 보통 토큰당 KV 엔트리 1개인데 m=2면 두 토큰당 1개(차원별 가중 결합)로 저장합니다. 공유: KV 공유는 메모리를, 희소 선택 위치(sparse position) 공유는 검색 연산을 줄이며 둘은 반드시 함께 쓰일 필요는 없습니다. 레이어 패턴은 Full → Reuse → Reuse → Reuse → Reindex. Full은 글로벌 KV와 Indexer K를 새로 만들고 Top-K도 새로 고릅니다. Reuse는 앞 Full 레이어의 KV와 선택 결과를 모두 재사용합니다. Reindex는 KV는 재사용하되 표현이 많이 바뀌었으므로 Top-K 선택만 현재 레이어에서 다시 계산합니다. 모든 모드에서 Main Q와 SWA KV는 현 레이어에서 따로 계산하고, Full/Reindex는 indexer Q도 계산합니다. CSA2의 풀네임은 슬라이드에 없어 논문 확인이 필요합니다.

반 전체 사진을 층마다 다시 찍지 않고 한 번 찍은 사진을 여러 층에서 돌려 쓰되, 몇 층 지나면 "누구를 자세히 볼지(Top-K)"만 다시 고르는 거예요.

CONCEPT 07 · p.12

FP4 글로벌 KV

CSA2가 "몇 개를 저장할지"를 줄인다면 FP4는 "엔트리당 몇 비트"를 줄입니다. 글로벌 KV는 FP4로 저장하고, post-training 단계에서 quantization-aware training을 적용합니다. 양자화에 민감한 SWA KV는 FP8을 유지합니다. 결과적으로 글로벌 KV는 890 bytes/token, 100만 토큰에 약 0.89GB입니다. 2주차 계산기로 같은 길이의 GQA-8·FP16 모델을 재 보면 이 숫자가 얼마나 작은지 체감됩니다.

공식: 890 B × 1,000,000 tokens ≈ 0.89 GB

메모를 깨알 글씨(4비트)로 쓰되, 틀리면 안 되는 최근 메모(SWA)는 조금 큰 글씨(8비트)로 써요.

CONCEPT 08 · p.10, 13

Bounded Replay

CED로 글로벌 KV는 인코더에서 만들지만, 디코더의 SWA KV는 디코더 각 레이어의 hidden state에 의존합니다. SWA 윈도우가 128이라도 깊은 레이어의 정확한 SWA 상태 복원에는 레이어 수만큼 의존 범위가 누적되어 약 20 × 128 = 2,560 토큰이 필요합니다. Bounded Replay는 복원을 마지막 128 프롬프트 토큰만 디코더에 재생하는 것으로 제한해 근사 로컬 상태를 만듭니다. 정확 복원 대신 bounded recomputation을 택한 것입니다.

대화를 이어가려고 지난 대화 전체를 다시 읽는 대신 "마지막 몇 문장"만 다시 읽고 시작하는 거예요. 완벽하진 않지만 충분히 자연스러워요.

CONCEPT 09 · p.15–22

Perceiver: byte array M vs latent array N

이미지·텍스트·3D 포인트클라우드를 한 구조로 다루려는 통합 모델입니다. 입력(byte array)은 M개 인덱스 × C 채널(ImageNet 224×224×3이면 M=50,176, C=3)이고, 입력에 self-attention을 걸면 O(M²)라 불가능합니다. Perceiver는 하이퍼파라미터 크기 N×D의 latent array가 입력을 cross-attention으로 읽고(Query N, Key M → O(MN)), latent끼리 self-attention(O(N²))을 반복한 뒤 마지막 latent를 pooling해 분류합니다. 입력이 아무리 커져도 latent 쪽 비용은 그대로입니다.

복잡도: self-attn(byte) O(M²) → cross-attn O(MN) + self-attn(latent) O(N²)

5만 장짜리 사진 뭉치를 전부 서로 비교하면 끝이 없으니, "메모장 N칸"이 사진 뭉치를 훑어 필요한 정보만 적고(cross-attention), 메모장끼리만 정리(self-attention)해요. 사진이 아무리 많아도 메모장 크기는 그대로예요.

CONCEPT 10 · p.23–27

Perceiver IO · Graph Perceiver IO

Perceiver는 분류처럼 출력이 작을 때만 쓸 수 있습니다. Perceiver IO는 출력 쿼리 배열(크기 M)로 latent(N)를 cross-attention해(Query M, Key N → 출력 M) 분할(segmentation)처럼 입력 크기의 구조화된 출력을 만듭니다. 그러나 노드 간 관계(그래프)는 다루지 못하므로, Graph Perceiver IO가 관계 정보를 결합합니다.

메모장(N)만 보고 "사진 한 장 전체 크기의 답(M)"을 다시 그려내려면, "질문 카드"를 사진 픽셀 수만큼 만들어 메모장에 물어보는 식이에요. Graph 버전은 "이 픽셀과 저 픽셀이 연결돼 있다"는 관계까지 알려줘요.

수업 중 토론 · PDF에 없음

벤치마크 vs 실사용, 오픈 웨이트 보안, GPU 자원

이 카드의 내용은 수업 요약본에만 있고 강의 슬라이드에는 없습니다. 수업 중 토론으로 표기합니다. 요약본의 "GPT-4, Claude 3 Opus와 대등한 벤치마크"도 PDF에 표가 없어 논문 확인 전에는 쓰지 않습니다.

벤치마크 점수가 높아도 실제 사용 시 체감 성능이 떨어질 수 있습니다. 벤치마크에 없는 다양한 실사용 프롬프트와 API 서빙 환경(하네스)의 차이가 원인으로 거론됐고, 이는 8주차의 "벤치마크 신뢰성" 주제로 이어집니다. 특정 국가에서 개발된 오픈 웨이트 모델에 학습 단계에서 심어진 백도어(특정 프롬프트에 반응)의 잠재 위험도 논의됐습니다. 마지막으로 DeepSeek식 아키텍처 실험의 성공은 막대한 GPU 자원 위의 수많은 시행착오의 결과일 가능성이 높아, GPU 자원이 연구의 폭과 깊이를 결정한다는 데 공감대가 있었습니다.

시험 점수가 높다고 실제 일을 잘하는 건 아닐 수 있고, 공짜로 받은 프로그램에 몰래 심어진 함정이 있을 수 있고, 새로운 설계를 많이 시도하려면 결국 비싼 컴퓨터가 많이 필요하다는 세 가지 이야기를 나눴어요.

5. 시험 포인트

  • KV 캐시 압축 4대 전략과 담당 기술 매칭: 엔트리 크기 ↓ FP4 / 엔트리 수 ↓ CSA2 compression / 레이어 중복 ↓ cross-layer reuse / 보관 기간 ↓ Bounded Replay
  • 구조 수치: 40 = 20E + 20D, 552B 백본 + 196B Engram, 8B(prefill) / 16B(decode) 활성, SWA 128, Top-512
  • CED의 핵심: 디코더 글로벌 K,V를 인코더 최종 hidden state에서 생성(인코더 K,V 직접 재사용 아님) → 긴 입력의 prefill은 인코더 20층만 → 연산 ≈ 1/2. 캐시 크기를 줄이는 게 아니라 계산량을 줄임
  • CED가 못 없애는 것: 디코더 SWA KV → Bounded Replay(마지막 128 토큰만 재생, 이론 의존 범위 20×128 = 2,560)
  • CSA2 레이어 패턴 Full → Reuse×3 → Reindex, 각 모드에서 새로 만드는 것 / 재사용하는 것
  • FP4는 글로벌 KV만, SWA KV는 FP8(양자화 민감). 890 B/token → 1M ≈ 0.89GB
  • mHC: 다중 residual stream + doubly stochastic 제약으로 안정성
  • Perceiver: byte M vs latent N, O(M²) → O(MN) + O(N²). Perceiver IO는 출력 쿼리 M으로 구조화 출력. Graph Perceiver IO는 관계 정보

예상 문제

Q1. DeepSeek-V4.1-Flash에서 글로벌 KV 캐시의 엔트리 수를 줄이는 기술과 엔트리당 비트 수를 줄이는 기술을 각각 쓰시오.
엔트리 수 ↓ = CSA2 compression(m=2, 두 토큰당 엔트리 1개). 비트 수 ↓ = FP4 양자화(post-training에서 QAT 적용, SWA KV는 FP8 유지). 해설: 4대 전략 중 ①②에 해당(p.4, 11~12).
Q2. CED(Causal Encoder-Decoder)가 prefill 연산을 절반으로 줄이는 원리를 설명하고, 그럼에도 Bounded Replay가 필요한 이유를 쓰시오.
디코더 각 레이어의 글로벌 K,V를 인코더 최종 hidden state로부터 생성하므로, 긴 입력은 인코더 20층만 통과하면 된다(N≫n_win일 때 ≈ 1/2). 그러나 디코더의 SWA(로컬) KV는 디코더 레이어별 hidden state에 의존하므로, 마지막 128 토큰만 디코더에 재생해 근사 로컬 상태를 만든다(정확 복원은 약 20×128 토큰 필요).
Q3. 글로벌 KV 캐시가 토큰당 890바이트일 때 1,000,000 토큰의 글로벌 KV 캐시 크기는? SWA KV가 FP8로 남는 이유도 쓰시오.
890 × 1,000,000 ≈ 0.89 GB. SWA KV는 양자화에 더 민감하므로 FP4가 아닌 FP8을 유지한다. 위 인터랙션에서 N=1M으로 두고 네 토글을 모두 켜면 논문 수치 막대와 비교할 수 있다.
Q4. (객관식) CSA2 레이어 패턴에서 "Reindex" 레이어가 하는 일로 옳은 것은? ① 글로벌 KV와 Top-K 선택을 모두 새로 계산 ② 글로벌 KV는 앞 Full 레이어 것을 재사용하고 Top-K 선택만 현재 레이어에서 재계산 ③ 모두 재사용 ④ SWA KV만 재사용
②. ①은 Full, ③은 Reuse의 설명이다. 모든 모드에서 Main Q와 SWA KV는 현 레이어에서 계산하므로 ④는 틀리다.
Q5. Perceiver가 224×224×3 이미지(M=50,176)에 self-attention을 직접 적용하지 않는 이유와, latent array(N)를 도입했을 때의 복잡도를 쓰시오. Perceiver IO는 무엇을 추가했는가?
직접 self-attention은 O(M²)로 과도하다. latent N을 두어 cross-attention O(MN) + latent self-attention O(N²)로 줄이며, M이 커져도 latent 쪽 비용은 불변이다. Perceiver IO는 출력 쿼리 배열(크기 M)로 latent를 cross-attention(Query M, Key N → 출력 M)해 분할 같은 구조화된 출력을 가능하게 했다.
