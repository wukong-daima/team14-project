우리는 "공부 사이트를 만들었다"가 아니라 "자가 진화 루프가 진짜로 개선하는지 쟀다"로 시작한다.

질문

모델 가중치를 바꾸지 않는 자가 진화 하네스가 학습 콘텐츠를 실제로 개선하는가?

개선분을 수업에서 배운 대로 쪼개면 무엇이 남는가?

Δ = O + T + G   오버피팅 · 테스트타임 스케일링 · 진짜 개선 (8주차 HDA)

8주차: 벤치마크 향상의 98%가 오버피팅이던 사례. 9주차: 부정확한 리워드는 루프를 엉뚱한 곳으로 보낸다. 그 경고를 우리 사이트에서 직접 재현한다.

실험 장치 = 우리가 만든 사이트

콘텐츠 주차 페이지 7개 (설명 두 벌 · 도형 · 인터랙션 · 모델 비교)

벤치마크 LectureBench-14: 공개 세트(루프가 봄) / 비공개 세트(평가 전용)

루프 진단 → 근거 수집 → 패치 → 검증 → PR (사람 머지)

보상 R = 0.6·Accpublic + 0.4·SourcePass

풀이자는 작은 모델(자료 없이) · 제안자는 큰 모델(문제를 보지 않음) · 유출 검사로 문제 베끼기 차단

데모 · 사이트가 가르치는 방식

1분. 슬라이더 → 쉬운 모드 버튼 → 비교표 순으로.

데모 · 루프가 재는 방식

분석 계획을 결과 보기 전에 고정해 뒀다는 점을 강조. 라운드가 있으면 분해 막대를 보여준다.

왜 O·T·G 로 쪼개는가

8주차 시뮬레이터. 하드코딩 규칙 제거(E_neutral)와 호출 수 맞추기(B_cc)가 우리 루프에서는 '비공개 세트'와 '호출 수 동일 설계'에 해당.

사전 등록한 것

항목고정값
보상R = 0.6·Acc_public + 0.4·SourcePass. 비공개 정답률은 보상에 쓰지 않음
분해O = Δ공개 − Δ비공개 · T = 0 (호출 수 동일) · G = Δ − O − T
채택유출 0 · HTML 정상 · R 상승 · 그래도 사람이 PR 검토
표본공개 150+ · 비공개 50+ · 라운드 ≥3 · 시드 3개 평균±표준편차
예상O 가 Δ의 절반 이상일 가능성이 큼. 그래도 숨기지 않음
