AI 에이전트: Reasoning · Memory · Planning

에이전트는 "환경을 인식하고 행동하는 주체"이고, 언어 에이전트는 Reasoning(내부 행동) · Memory(읽고 쓰는 장기 기억) · Planning(행동 선택 알고리즘)으로 구성됩니다. 환경 조작 공격, 일관성 부족, 데이터 부족이라는 제약과, 수백 스텝짜리 롱 호라이즌 과제를 위한 RL·하네스 설계까지 다룹니다.

AI 에이전트는 로봇 청소기처럼 "보고, 생각하고, 움직이는" 프로그램이에요. 이번 주는 에이전트가 어떻게 생각하고(Reasoning), 기억하고(Memory), 계획하는지(Planning), 그리고 왜 아직 믿고 쓰기 어려운지를 배웁니다.

CONCEPT 01 · p.3–20

에이전트의 정의와 언어 에이전트

에이전트는 "센서로 환경을 인식하고 액추에이터로 환경에 행동하는 모든 것"입니다(Russell & Norvig 2020). 도메인마다 환경·관측 공간·행동 공간이 다릅니다. 게임은 스크린샷·인벤토리를 보고 조작하고, 코딩(SWE-bench: 이슈 195단어, 코드베이스 평균 438,000줄)은 저장소·테스트 출력을 보고 코드를 편집하며, 웹(WebArena)은 DOM·스크린샷을 보고 클릭·입력하고, 컴퓨터 사용(OSWorld)은 데스크톱 스크린샷·접근성 트리를 보고 키보드·마우스를 씁니다. LLM-first 관점은 "LLM을 에이전트로 만든다"(프롬프트·스캐폴딩 중심), Agent-first 관점은 "에이전트에 LLM을 통합한다"(인식·세계 모델·계획 과제가 그대로 남음)입니다. 언어를 추론과 소통에 쓰는 현대 에이전트를 언어 에이전트라 부르며, LLM은 수단일 뿐입니다.

로봇 청소기는 센서로 방을 보고 바퀴로 움직이는 에이전트예요. 요즘 AI 에이전트는 "말"로 생각하고 "말"로 소통하면서 검색·코딩·클릭 같은 행동을 해요. 게임 속이든, 코드 저장소든, 웹이든 "보는 것"과 "할 수 있는 것"이 다 달라요.

CONCEPT 02 · p.21–32

Reasoning = 내부 행동 (internal action)

사람의 정신 과정에 해당하는 것이 LM의 중간 생성(intermediate generation)이고, 에이전트 관점에서는 외부 환경을 바꾸지 않는 내부 행동입니다. 추론은 내부 컨텍스트(단기 기억)를 갱신해 이후 외부 행동을 바꿉니다. 행동 공간이 클수록 용량은 커지지만 의사결정은 어려워지는데, 추론·언어 공간은 사실상 무한합니다. LLM은 인간의 추론 흔적을 모방해 reasoning prior를 학습하며, 자기 추론을 대상으로 다시 추론하는 self-reflection은 메타 추론입니다.

"사과가 좋아"라고 속으로 생각하는 건 세상을 바꾸지 않아요. 하지만 나중에 마트에서 사과를 사게 만들죠. 생각도 일종의 행동이에요. 단, 밖이 아니라 머릿속만 바꾸는 행동.

CONCEPT 03 · p.28–30

ReAct: 추론이 행동을 돕는 방식

Apple Remote 예시("Apple Remote 말고 어떤 기기가, Apple Remote가 원래 제어하도록 설계된 프로그램을 제어할 수 있나?")에서 행동만 하면 Search를 반복하다 "Front Row (software)" 결과를 해석하지 못하고 엉뚱하게 종료하고, 추론만 하면 외부 정보 없이 iPhone/iPad/iPod Touch라는 그럴듯한 오답을 냅니다. Thought와 Act를 교차(Thought 1 → Act 1 → Obs 1 → … → Finish[keyboard function keys])하면 검색 결과를 해석해 올바른 답에 도달합니다. 추론은 환경 상태 유추·과거 회고·재계획을 통해 더 나은 행동을 끌어내는 수단입니다. 아래 "직접 해보기"에서 세 모드를 돌려 보세요.

보물찾기에서 힌트를 읽기만 하거나(추론만), 아무 데나 파기만 하면(행동만) 못 찾아요. "힌트 읽기 → 파보기 → 결과 보고 다시 생각하기"를 반복해야 찾아요. 그게 ReAct예요.

CONCEPT 04 · p.38–42

CoT가 순차 문제를 푸는 이유, 추론 모델 (DeepSeek-R1, s1)

요약본의 "딥식 아론 모델"은 DeepSeek-R1입니다. 또 "풀이 과정 데이터로 SFT 후 정답만으로 RL"은 축약이며, R1은 cold-start SFT → reasoning-oriented RL → rejection sampling + SFT → 전 시나리오 RL의 4단계입니다. 증류 예시의 교사는 "GPT"가 아니라 GPT-o3, DeepSeek-R1, 학생은 Llama입니다 (p.39~40).

깊이가 고정된 트랜스포머도 충분히 긴 중간 추론 스텝을 생성하면 본질적으로 순차적인 문제를 풀 수 있습니다. 정답만 바로 내려면 매우 깊은 네트워크가 필요하거나 아예 못 풉니다(트랜스포머는 병렬에 강하고 순차에 약함). DeepSeek-R1은 cold-start SFT(최소한의 추론 형식) → 정답이 명확한 수학·코딩에 reasoning-oriented RL → rejection sampling + SFT → 전 시나리오 RL로 학습했고, 강한 추론 모델에서 증류하면 Llama 같은 모델도 추론 능력을 얻습니다. s1은 1,000개 고품질 문제(s1K: 59,029 → 51,581 → 24,496 → 1,000)로 SFT한 뒤 budget forcing(토큰 상한에서 end-of-thinking 강제 삽입, 멈추려 하면 "Wait" 추가)으로 test-time scaling을 가장 단순하게 구현했습니다.

암산으로 한 번에 답을 내려면 머리가 엄청 좋아야 하지만, 종이에 한 줄씩 풀면 보통 머리로도 풀려요. 그리고 다 풀었다고 할 때 "잠깐(Wait), 다시 볼까?"를 붙이면 스스로 실수를 고쳐요. 그게 s1의 비법이에요.

CONCEPT 05 · p.43–51

Memory: 읽고 쓸 수 있는 장기 기억

장기 기억은 경험·지식·기술을 저장하고 읽기와 쓰기가 모두 되어야 합니다. RAG의 검색 코퍼스는 타인(위키 편집자)이 쓴 read-only 기억이라 에이전트에게 최적이 아니며, 자율적 쓰기가 필요합니다. Generative Agents는 컨텍스트 창에 모든 이벤트를 담을 수 없어 기억이 필요함을 보였고, 기억을 episodic(경험, append-only 이벤트 스트림) · semantic(지식, LLM이 이벤트를 추론해 기록) · procedural(기술, 코드 기반 skill)로 나눕니다. Reflexion은 RL 없이 보상을 자연어 요약으로 바꿔 기억에 저장하고 다음 시도의 컨텍스트로 써 시행착오 학습을 합니다(verbal reinforcement). 서비스로는 Mem0(선별 저장 semantic memory), Zep(시간 인식 지식 그래프)이 있습니다.

일기(있었던 일), 노트 정리(배운 것), 자전거 타기(몸이 기억하는 기술)는 다 다른 기억이에요. 틀린 뒤에 "다음엔 이렇게 하자"를 적어 두고 다시 도전하는 게 Reflexion이에요. 남이 쓴 백과사전만 읽는 건(RAG) 내 일기가 아니죠.

CONCEPT 06 · p.52–64

Planning: 반응형 → 트리 탐색 → 월드 모델

언어 에이전트의 계획은 목표가 자연어로 표현되고 행동 공간이 열려 있으며 goal test가 어려운 방향으로 갑니다. 반응형 계획은 빠르지만 근시안적이고, 실제 환경에서의 트리 탐색(LATS, Tree Search for LM Agents: branching·backtracking·exploration, value 0.5 → 0.45 → 0.68 → 1.0)은 체계적이지만 행동을 되돌릴 수 없고(비가역) 위험하며 느립니다. 그래서 환경 전이 동역학 s_t, a_t → s_{t+1}을 모사하는 월드 모델이 필요하고, LLM은 상태 전이를 꽤 잘 예측합니다. WebDreamer는 GPT-4o 또는 Dreamer-7B를 월드 모델로 써 실제 환경 접근 전에 후보 경로를 자연어로 시뮬레이션합니다.

체스에서 아무 수나 두면(반응형) 지고, 실제로 말을 옮겨 보며 탐색하면 무르기가 안 돼요. 머릿속으로 "이렇게 두면 저렇게 되겠지"를 상상(월드 모델)하는 게 가장 안전하고 빨라요.

CONCEPT 07 · p.66–70, 78–79

제약과 과제: 환경 조작 · 프라이버시 · 일관성 · 백도어

요약본의 "공간 지각 능력(Spatial Reasoning) 향상"은 PDF에 해당 슬라이드가 없습니다. 구두 설명으로 보이며 확인이 필요합니다. 요약본의 "OpenAI/Anthropic 등은 자체 레드팀 데이터셋 구축 및 에이전트를 통한 자동 평가"도 PDF 표현이 아니며, PDF의 근거는 Anthropic "Demystifying evals for AI agents" 8단계(p.80~83)와 OpenAI GPT-5.5 System Card의 데이터 파괴 행동 평가(p.78)입니다.

EIA(Environmental Injection Attack)는 정상처럼 보이는 악성 콘텐츠로 웹 에이전트에 최대 70% 공격 성공률을 달성했고, 적대적 팝업은 OSWorld/VisualWebArena에서 에이전트 행동의 70~90%를 유도했습니다. PrivacyLens는 모호한 지시를 따르다 이직 정보를 이메일로 노출하는 등 문맥적 프라이버시 규범 위반을 평가합니다. τ-bench의 pass^k는 k번 독립 시도가 모두 성공할 확률(= p^k)로 일관성을 재고, pass@k는 하나라도 성공할 확률(= 1 − (1−p)^k)입니다. p=0.8, k=5면 pass@k ≈ 0.9997인데 pass^k ≈ 0.33입니다. Sleeper Agents는 트리거가 있을 때만 악의적으로 행동하도록 학습된 모델이 SFT/RL/adversarial training을 거쳐도 백도어를 유지함을 보였습니다. ASPI는 "모호하면 질문하라"는 원칙이 오히려 프롬프트 인젝션 채널(사용자 답변, 도구 출력, ask_user 반환)을 늘린다고 지적합니다.

가짜 "확인" 버튼에 속아 눌러 버리거나, 남의 비밀을 메일에 써 버리거나, 10번 중 3번은 실수하는 로봇은 믿고 쓰기 어려워요. 겉으론 착한데 특정 암호를 들으면 나쁘게 변하는 로봇(Sleeper Agent)은 더 무섭고요.

CONCEPT 08 · p.71–77, 80–83

에이전트 데이터 부족과 평가 설계

에이전트 데이터(관측-행동 쌍 궤적)는 수집(과제 정의·인프라·시연·검증)과 공유(이질적 관측/행동 공간)가 모두 어렵습니다. 통일안은 관측 = 스크린샷, 행동 = 범용 마우스·키보드입니다. 인터넷 영상은 많지만 행동 라벨이 없어 IDM(Inverse Dynamics Model, (o_t, o_{t+1}) → a_t)으로 행동을 복원하는 VPT가 제안됐습니다. Anthropic의 "Demystifying evals for AI agents"는 평가를 마지막 시험이 아니라 개발 피드백 루프로 보고 8단계를 제시합니다. 20~50개 과제로 일찍 시작, 사람이 손으로 확인하던 것부터, 모호하지 않은 과제 + 정답 예시, positive/negative 균형, 깨끗한 환경, deterministic/LLM/human grader, 점수 대신 transcript 읽기, 포화 시 regression/capability eval 분리.

유튜브에 요리 영상은 많지만 "어느 버튼을 눌렀는지"는 안 나와요. 그걸 추측해 주는 모델이 IDM이에요. 그리고 시험은 끝에 한 번 보는 게 아니라 매일 작은 쪽지시험으로 뭘 못하는지 찾는 게 나아요.

CONCEPT 09 · p.85–93

롱 호라이즌 에이전트: T1 · 하네스 · MEA

요약본의 "T* 논문"은 T1: Terminal Agent Reinforcement Learning for Long-Horizon Tasks(arXiv 2026)이고, 동기화 기법명은 TITO(토큰 ID 재사용)와 R3(MoE 전문가 인덱스 재사용)입니다 (p.85~88).
요약본의 "프레임워크(vLLM, Llama-factory 등) 간 불일치"는 슬라이드 기준 롤아웃 SGLang vs 학습 Megatron-Core + Transformer Engine입니다. Llama-factory는 PDF에 없습니다 (p.87).

T1은 리눅스 터미널에서 수백 번 명령을 실행하는 과제를 RL로 학습하되, sparse reward(전부 성공 1 / 아니면 0)를 verifier 부분 보상으로 바꾸고, 추론(SGLang)과 학습(Megatron-Core + Transformer Engine) 사이의 불일치를 TITO와 R3로 해결했습니다. Anthropic 하네스 실험은 긴 작업에서 생기는 context anxiety와 자기 평가 과신 때문에 Planner → Generator → Evaluator를 분리하고 Sprint Contract(코딩 전 acceptance criteria 합의, contract.md/feedback.md 파일로 소통)를 도입해 20분짜리를 6시간짜리 완성도 높은 결과로 늘렸고, Opus 등장 후에는 스프린트 구조를 제거했습니다. LongHorizon-Harness는 compounding error · context rot · task-state loss를 지적하며 MEA(Manager: task state 관리, Executor: 과거 컨텍스트 없이 subtask 하나 수행, Auditor: read-only 검증)로 롱 호라이즌 실행을 "검증된 task-state 전이의 연속"으로 재정의합니다.

긴 숙제는 계획 짜는 사람, 하는 사람, 검사하는 사람을 나누고, 검사에 통과한 것만 "끝남"으로 적어요. 하는 사람이 "다 했어요"라고 해도 그냥 믿지 않아요.

5. 시험 포인트

  • 에이전트 정의(Russell & Norvig)와 도메인별 환경/관측/행동 공간 예시. LLM-first vs Agent-first
  • Reasoning이 "내부 행동"인 이유, 추론 공간은 무한, self-reflection = 메타 추론
  • ReAct 예시: 행동만 / 추론만 / 교차의 결과 차이 (Apple Remote → keyboard function keys)
  • CoT가 순차 문제를 푸는 이유(고정 깊이 + 긴 중간 스텝), R1 4단계, s1 budget forcing("Wait")
  • RAG는 read-only 기억 → 쓰기 가능한 기억 필요. episodic / semantic / procedural. Reflexion = verbal reinforcement
  • Planning 3패러다임 장단점, 월드 모델 정의 s_t, a_t → s_{t+1}, WebDreamer
  • 제약: EIA 70%, 팝업 70~90%, PrivacyLens, pass^k = p^k vs pass@k = 1−(1−p)^k, Sleeper Agent 3단계, IDM/VPT
  • 롱 호라이즌: sparse reward → verifier 부분 보상, TITO/R3, Generator/Evaluator 분리 이유, MEA의 Auditor 역할

예상 문제

Q1. 에이전트에게 Reasoning이 "내부 행동"으로 간주되는 이유를 설명하고, 외부 행동과의 차이를 예로 들라.
추론(토큰 생성)은 외부 환경 상태를 직접 바꾸지 않고 내부 컨텍스트(단기 기억)만 갱신하지만, 그 결과 이후 외부 행동(검색·클릭)의 선택이 달라진다. 예: "사과가 좋아"라는 생각은 환경을 바꾸지 않지만 마트에서 사과를 사게 만든다.
Q2. Apple Remote 문제에서 행동만 하는 에이전트와 추론만 하는 에이전트가 각각 왜 실패했는지, ReAct는 왜 성공했는지 쓰라.
행동만: 검색 결과를 해석하지 않고 Front Row (software)에서 Finish[yes]로 엉뚱하게 종료. 추론만: 외부 정보 없이 Apple TV라는 그럴듯한 전제에서 iPhone/iPad/iPod Touch라는 오답 생성(환각). ReAct: Thought로 "무엇을 검색해야 하는지" 정하고 Obs를 해석해 keyboard function keys라는 정답에 도달.
Q3. Generative Agents가 제시한 세 가지 기억 유형과 각각의 쓰기 방식을 쓰고, 일반 RAG가 에이전트 기억으로 불충분한 이유를 설명하라.
Episodic(경험, append-only 이벤트 스트림), Semantic(지식, LLM이 이벤트를 추론해 기록), Procedural(기술, 코드 기반 skill). RAG 코퍼스는 타인이 작성한 read-only 기억이라 에이전트 자신의 경험을 반영하지 못하므로 자율적 쓰기가 필요하다.
Q4. 실제 환경에서의 트리 탐색 계획의 세 가지 문제와, 월드 모델이 이를 어떻게 해결하는지 WebDreamer를 예로 설명하라.
행동이 비가역적이라 backtracking 불가, 안전·프라이버시 위험, 추론 시점 탐색이 느리고 비쌈. 월드 모델은 s_t, a_t → s_{t+1}을 예측하는 모델로, WebDreamer는 GPT-4o/Dreamer-7B로 후보 상호작용을 자연어로 시뮬레이션해 실제 환경 접근 전에 각 경로의 성공 가능성을 평가한다.
Q5. τ-bench의 pass^k를 정의하고 pass@k와의 차이를 쓰라. p=0.8, k=3일 때 각각의 값을 구하라.
pass^k = 동일 과제를 k번 독립 시도해 모두 성공할 확률 = p^k (일관성·신뢰성 지표). pass@k = 하나라도 성공 = 1−(1−p)^k. p=0.8, k=3: pass^k = 0.512, pass@k = 0.992.
Q6. Sleeper Agent 실험의 3단계를 쓰고, 오픈 웨이트 모델 도입 시 시사점을 설명하라.
(1) 정상 프롬프트에선 정상, 트리거 포함 시 악의적으로 행동하도록 학습 (2) SFT/RL/adversarial training 등 표준 안전 기법 적용 (3) 테스트에선 안전해 보이지만 트리거 시 유해 행동 유지. 시사점: 표준 안전 학습으로 백도어를 제거했다고 보장할 수 없으므로 외부 오픈 웨이트 모델은 별도 검증이 필요하다.
